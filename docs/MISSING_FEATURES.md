# Inventory Management System — Missing Features

This document records the functionality that is missing or only partially implemented in the current application. It is intended to serve as a product backlog and implementation reference.

## Current baseline

The application currently provides a basic Laravel POS workflow covering:

- User authentication, registration, email verification, password reset, profile, and password change.
- Supplier, customer, unit, category, and basic product masters.
- Purchase entry, pending purchase approval, and quantity increase after approval.
- Sales invoice entry, pending invoice approval, stock validation, and quantity decrease after approval.
- Full, partial, and due customer payments.
- Basic stock, purchase, invoice, supplier-wise, product-wise, and customer payment reports.
- Invoice and report print/PDF views.

The legacy system still stores a compatibility quantity on each product, while the ERP foundation now maintains transaction-based inventory movements, warehouse locations, accounting journals, and enterprise authorization alongside it. Several advanced workflows remain partial and are tracked below.

### Implemented in the initial ERP foundation upgrade

The first foundation slice has now been added to the codebase:

- Company, branch, department, warehouse, store, and user organization fields.
- Roles, permissions, role-user assignments, and permission-role assignments.
- Warehouse location hierarchy for warehouse, zone, rack, shelf, and bin records.
- Immutable inventory movement records and a reusable inventory ledger service.
- Audit-log storage and approval audit events.
- Approved purchase receipt and sales issue movements, while retaining the legacy product balance for compatibility.
- Initial system administrator role and core permission seed data.
- Product master extension with brand, SKU, barcode, HSN/SAC, pricing, tax, stock thresholds, and batch/serial tracking mode.
- Stock movement ledger report with product, movement-type, and date filters.
- Controlled stock adjustment workflow with reason codes, approval/rejection, quantity locking, audit events, and ledger postings.
- Location-based inventory transfer workflow with source/destination validation and paired ledger movements.
- Organization and location setup screens for companies, branches, warehouses, and storage locations.
- Purchase-order and goods-receipt workflow with partial-receipt quantities and stock posting on receipt approval.
- Sales-order and delivery workflow with partial-delivery quantities and stock issue on delivery approval.
- Customer sales returns and supplier purchase returns with approval, stock impact, audit, and ledger movements.
- Batch/lot/serial receipt metadata with manufacturing, expiry, best-before, warranty fields, and serial-count validation.
- FIFO cost layers, cost consumption records, and stock valuation report for new ledger movements.
- Finance configuration tables for currencies, exchange rates, tax rates, fiscal years, and numbering sequences.
- Chart of accounts, journal entries, journal lines, balanced debit/credit validation, and accounting posting service.
- Chart-of-accounts administration and journal-entry visibility screens.
- Configurable automatic account mappings for inventory receipt, COGS, loss, and related journal postings.
- Planning exception report for low, excess, slow-moving, and dead stock.
- Purchase suggestion report based on reorder level and target stock.
- Sales-order stock reservations with automatic release as deliveries are approved.
- Sales invoice subtotal, tax, grand-total fields and product-tax calculation service.
- A legacy backfill command: `php artisan erp:backfill-inventory-ledger`.

These tables and services form a backward-compatible ERP foundation; advanced workflow depth, external integrations, and complete enterprise controls remain tracked below.

## Technical foundation required

The following work should be completed before implementing advanced modules:

1. Create an immutable inventory movement ledger and derive balances from approved movements.
2. Add company, branch, warehouse, store, and location relationships.
3. Replace monetary `double` fields with fixed-precision decimal fields. Migration `2026_09_11_000117` converts legacy product, purchase, invoice-detail, and payment quantity/amount columns and adds matching model casts.
4. Add foreign keys, indexes, uniqueness rules, and database-level constraints.
5. Add roles, permissions, approval policies, and maker/checker enforcement.
6. Add soft deletes and audit/version history for business records.
7. Introduce document status machines instead of only pending/approved flags.
8. Add tax, currency, fiscal-period, and numbering-sequence foundations.
9. Add automated feature tests using a working isolated test database.
10. Replace static dashboard values with computed queries and cached reporting services.
11. Add validation for dates, quantities, prices, discounts, references, and cross-record ownership.
12. Establish document attachment storage, access control, backup, and retention policies.
